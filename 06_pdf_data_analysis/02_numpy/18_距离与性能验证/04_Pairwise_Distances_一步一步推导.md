## 一、先确定：我们究竟想算什么

### 先用日常语言说明这个案例

**这个案例可以理解为：在三维空间里，有两组点，我们想知道第一组的每个点，到第二组的每个点，直线距离分别是多少。**

例如，把仓库里三个待取货物的位置记为 A、B、C，把两个作业点的位置记为 P、Q。如果想比较每件货物离哪个作业点更近，就要先分别算出它到 P、Q 的距离，不能只算 A 到 P、B 到 Q。

这里先只解决“所有这些距离是多少”，不考虑实际搬运路线、障碍物或如何分配任务。课件也没有规定具体业务场景；仓库只是帮助理解的比喻。

### 先分清：一个点、一项坐标和一组点分别是什么

想象你要告诉别人一个物体在仓库中的位置。只说“左右方向的位置是 8.54”，够不够？

不够，因为它可能在不同的前后位置、不同的高度。还需要另外两个方向的位置，才能确定这个三维点。

因此，把三个坐标放在一起，才是在描述一个点：

```text
A = (8.54, 1.54, 8.12)
     左右  前后  上下
```

三个方向的叫法只是直观解释；关键是它们是在同一套坐标系下、按相同顺序记录的三个坐标。

**所以不是每个数各代表一个点，而是每一行的三个数，共同描述一个点。**

接下来才把这些位置放进数组。课件使用 `x`、`y` 作为两组数组的变量名：

- `x` 保存第一组点 A、B、C。
- `y` 保存第二组点 P、Q。

**这里的数组名 x、y，不是数学中表示横坐标、纵坐标的两个坐标值。** 如果把它们理解成 `points_a`、`points_b`，也就是“第一组点”“第二组点”，就不容易混淆。

### 看看这两组点在代码里怎样保存

```python
import numpy as np

# 每一行表示一个点，每个点有三个坐标。
x = np.array([
    [8.54, 1.54, 8.12],
    [3.13, 8.76, 5.29],
    [7.73, 6.71, 1.31],
])

y = np.array([
    [8.65, 0.27, 4.67],
    [7.73, 7.26, 1.95],
])
```

把每行对应的点标出来，就能读懂这些数据：

| 集合 | 点的名字 | 第 0 个坐标 | 第 1 个坐标 | 第 2 个坐标 |
|---|---|---:|---:|---:|
| x | A，即 x[0] | 8.54 | 1.54 | 8.12 |
| x | B，即 x[1] | 3.13 | 8.76 | 5.29 |
| x | C，即 x[2] | 7.73 | 6.71 | 1.31 |
| y | P，即 y[0] | 8.65 | 0.27 | 4.67 |
| y | Q，即 y[1] | 7.73 | 7.26 | 1.95 |

再把代码中的三个层次对照一次：

| 写法 | 表示什么 | 为什么 |
|---|---|---|
| `x` | A、B、C 这一整组点 | 数组里有三行位置记录 |
| `x[0]` | 点 A 的完整坐标 `[8.54, 1.54, 8.12]` | 选出第 0 行，保留该点的三个坐标 |
| `x[0, 0]` | 点 A 的第 0 个坐标值 `8.54` | 在第 0 行里，再选第 0 列，只剩一个数 |

这里还要区分两种“维度”：`x` 是按行、列组织的**二维数组**，但每行保存的是一个**三维空间点**。前者描述数据的组织方式，后者描述确定一个点需要几个坐标，并不矛盾。

现在再读任务：**A、B、C 中的每一个点，分别到 P、Q 有多远？**

它问的是两整行坐标所描述的两个点之间的距离，不是把 `x`、`y` 两个变量当成某一个点的横纵坐标。

### 先想一下：只算 A 到 P、B 到 Q，任务完成了吗？

还没有。

因为“每一个 x 点，分别比较每一个 y 点”要求：

- 对 A：需要 A→P、A→Q。
- 对 B：需要 B→P、B→Q。
- 对 C：需要 C→P、C→Q。

### 先不要记形状：我们一行一行搭出距离表

先只考虑 A。它到 P、Q 的距离可能不同，所以需要分开记两项：

| 起点 | 到 P 的距离 | 到 Q 的距离 |
|---|---|---|
| A | A→P | A→Q |

为什么要分两列距离？因为有两个终点，我们要知道每个数到底对应哪一个终点，不能把 A→P 和 A→Q 混成一个数。

接下来，B 也要分别到 P、Q。沿用同样的两个距离列，为 B 增加一行：

| 起点 | 到 P 的距离 | 到 Q 的距离 |
|---|---|---|
| A | A→P | A→Q |
| B | B→P | B→Q |

C 也有自己的两项距离，再增加一行：

| 起点 | 到 P 的距离 | 到 Q 的距离 |
|---|---|---|
| A | A→P | A→Q |
| B | B→P | B→Q |
| C | C→P | C→Q |

这样就不是先背“3 行 2 列”，而是从记录需求得到它：

- 每增加一个 x 点，就增加一行，用来单独记录它到各个 y 点的距离。
- 每增加一个 y 点，就增加一列距离，因为每个 x 点都要多比较这个终点。

在这个安排下，三个 x 点占三行，两个 y 点占两列距离，所以是 3×2=6 个距离。

注意，表格最左边的“起点”列只是帮助阅读的标签，不计入距离数组的列数；表头也不算数据行。真正保存的数值按下面的位置排列：

```text
[
    [A到P的距离, A到Q的距离],
    [B到P的距离, B到Q的距离],
    [C到P的距离, C到Q的距离]
]
```

### 先想一下：如果安排成 2 行 3 列，也正确吗？

正确，但行、列的含义必须跟着交换。

我们可以让 P、Q 分别占一行，把 A、B、C 放在列上：

| 起点 / 终点 | A | B | C |
|---|---|---|---|
| P | P→A | P→B | P→C |
| Q | Q→A | Q→B | Q→C |

为什么这样也能记录同样的答案？因为这里求的是没有方向区别的欧氏直线距离：A 到 P 与 P 到 A 一样远。六对点没有改变，只是这些距离在表里的位置变了。

所以，两种安排都成立：

| 安排 | 行代表什么 | 列代表什么 | 数值数组的形状 |
|---|---|---|---|
| 课件采用的安排 | x 中的点 A、B、C | y 中的点 P、Q | `(3, 2)` |
| 交换行列后的安排 | y 中的点 P、Q | x 中的点 A、B、C | `(2, 3)` |

因此，准确的说法不是“结果在数学上必须是 3 行 2 列”，而是：

> **课件约定行对应 x 点、列对应 y 点，因此这套代码的结果是 3 行 2 列；交换行列的约定，也可以用 2 行 3 列记录同样六段距离。**

关键不是坚持某一种形状，而是每个位置始终对应正确的一对点。等后面算出距离数组 `dists` 后，`dists.T` 可以交换行列，得到另一种安排；不能只用 `reshape(2, 3)` 随意重新分行，因为那不会按原来的点对关系交换两个轴。

为了和课件代码一致，后续统一采用第一种安排：**行是 x 点，列是 y 点。**

注意：每个点有三个坐标，不代表一个格子最终要放三个距离。三个坐标共同决定这两个点之间的**一个**距离。

这就产生了下一步的问题：一个格子里的距离，到底怎样从三个坐标算出来？

## 二、先不要想数组：两个点之间的距离怎么算

### 先想一下：两个点在一条直线上，为什么要先相减？

假设一人在位置 2，另一人在位置 5，他们相隔 3。

相减 `2 - 5 = -3` 描述的是带方向的位置差；距离不应为负，因此直线距离是它的绝对值 3。

当点在平面上时，只看一个方向的差还不够。例如从 `(0, 0)` 到 `(3, 4)`，横向差 3、纵向差 4，直线距离既不是 3，也不是 4。

两个方向互相垂直，可以用勾股定理：

```text
距离的平方 = 横向差的平方 + 纵向差的平方
           = 3² + 4²
           = 9 + 16
           = 25

距离 = √25 = 5
```

再多一个空间方向，推导方式不变：先得到平面距离，再与第三个垂直方向结合。

```text
空间距离的平方 = 第 0 个坐标差² + 第 1 个坐标差² + 第 2 个坐标差²
```

因此，我们不是随意选择“相减、平方、求和、开根号”这四步：

| 动作 | 为什么需要它 |
|---|---|
| 对应坐标相减 | 知道两个点在每个方向上差了多少 |
| 每个差分别平方 | 配合勾股定理；正负方向不会相互抵消 |
| 将同一对点的三个平方相加 | 合并三个方向的差异，得到距离的平方 |
| 开平方 | 从“距离的平方”还原成距离，恢复原来的长度单位 |

> 这里算的是欧氏距离，也就是通常说的直线距离。不是把差值直接加起来，也不是把绝对值加起来；后者属于另一种距离定义。

## 三、拿课件中的一对点，先真的算一遍

我们先只解决空表左上角：A 到 P，也就是 `x[0]` 到 `y[0]`。

### 先想一下：需要取出的是一行，还是一个数？

一个点有三个坐标，先取完整的一行，才能同时比较三个方向。

```python
# x[0] 是第一个 x 点的全部坐标，shape 为 (3,)。
point_a = x[0]

# y[0] 是第一个 y 点的全部坐标，shape 也为 (3,)。
point_p = y[0]

print("\n===== A 和 P 的坐标 =====")
print(point_a)
print(point_p)
```

```text
[8.54 1.54 8.12]
[8.65 0.27 4.67]
```

现在两行中的位置含义一致，所以可以直接逐项相减：

```python
one_difference = point_a - point_p

print("\n===== A 到 P 的三个坐标差 =====")
print(one_difference)
```

```text
[-0.11  1.27  3.45]
```

它对应三笔计算：

```text
8.54 - 8.65 = -0.11
1.54 - 0.27 =  1.27
8.12 - 4.67 =  3.45
```

### 先想一下：现在得到的三个数，是三个距离吗？

不是。它们仍然是同一对点的三个**坐标差**，其中还可能有负数。

我们接着按照上一节推导的距离定义处理：

```python
# ** 2 是逐元素平方：三个坐标差分别平方，不是整个数组相乘一次。
one_squared = one_difference ** 2

print("\n===== 三个坐标差分别平方 =====")
print(one_squared)
```

```text
[ 0.0121  1.6129 11.9025]
```

```python
# np.sum 的第一个参数是要汇总的数组。
# 这里是一维的三个数；不指定 axis 时，直接把这三个数加起来。
one_squared_distance = np.sum(one_squared)

print("\n===== A 到 P 的距离平方 =====")
print(one_squared_distance)
```

手算是：

```text
0.0121 + 1.6129 + 11.9025 = 13.5275
```

实际浮点打印可能显示为 `13.527499999999995`，这是二进制浮点表示带来的微小误差，不是公式不同。

```python
# np.sqrt 的参数是要开平方的数或数组。
# 传入一个数就返回对应平方根；传入数组则逐项开平方。
one_distance = np.sqrt(one_squared_distance)

print("\n===== A 到 P 的距离 =====")
print(one_distance)
```

得到约 `3.67797499`。

到这里，我们已经知道一个格子怎样计算。接下来才有理由问：怎样把这件事对所有格子做一遍？

## 四、先用双循环逐对计算，完成整张距离表

### 先想一下：要让每个 x 点都遍历每个 y 点，需要几层循环？

一层循环选 x 点，另一层循环选 y 点。

如果只写一层循环，让两个数组同位置配对，那就会回到“A 只比较 P，B 只比较 Q”的问题，遗漏其他组合。

```python
# x.shape[0] 是 x 的行数，本例为 3；y.shape[0] 为 2。
# 两个长度组成 (3, 2)，对应最开始画出的距离表。
# np.zeros(shape, dtype=...) 创建指定形状、初始全为 0 的数组。
# dtype=float 让结果可以保存带小数的距离。
loop_distances = np.zeros((x.shape[0], y.shape[0]), dtype=float)

for i in range(x.shape[0]):
    # 固定一个 x 点后，把所有 y 点都走一遍。
    for j in range(y.shape[0]):
        # 此时 x[i] 和 y[j] 都只代表一个点的三个坐标。
        current_difference = x[i] - y[j]

        # 同一对点的三个坐标差：分别平方，再合并，最后开平方。
        current_squared_distance = np.sum(current_difference ** 2)
        loop_distances[i, j] = np.sqrt(current_squared_distance)

print("\n===== 双循环得到的距离表 =====")
print(loop_distances)
```

```text
[[ 3.67797499  8.45241977]
 [10.14568381  5.87925165]
 [ 7.32185769  0.84386018]]
```

### 我们为什么先写这段比较长的代码？

因为循环把问题的结构直接展示了出来：

```text
固定 i=0：计算 x[0] 对 y[0]、y[1]
固定 i=1：计算 x[1] 对 y[0]、y[1]
固定 i=2：计算 x[2] 对 y[0]、y[1]
```

这段代码没有错，也不是“过时方法”。它一方面帮助我们弄清楚比较顺序，另一方面提供一个容易核对的参考结果。

但如果 x 和 y 的行数很多，我们就要在 Python 层面反复进入双循环。下一步想借用 NumPy 的批量运算，把这层层配对交给数组操作完成。

**真正的新问题不是“怎样把代码缩短”，而是“怎样让数组明确表达两个独立的选点动作”。**

## 五、为什么不能直接写 x - y

先看两张表的形状：

```python
print("\n===== 两组点原来的形状 =====")
print(x.shape)
print(y.shape)
```

```text
(3, 3)
(2, 3)
```

两个 3 虽然数值相同，含义却不同：

```text
x.shape = (3, 3)
           │  └─ 每个点有 3 个坐标
           └──── x 有 3 个点

y.shape = (2, 3)
           │  └─ 每个点有 3 个坐标
           └──── y 有 2 个点
```

### 先想一下：逐项相减会自动知道我们要“所有组合”吗？

不会。

数组相减先按形状对齐，并不会根据我们的业务意图自动增加配对轴。

直接做 `x - y`，右侧的坐标长度 3 对 3 没问题，但左侧的点数 3 对 2 对不上。按 NumPy 的形状规则，这两组输入不能直接相减，会报形状不兼容的 `ValueError`。这里先知道直接相减行不通；具体怎样判断形状能不能配合，我们会在第九部分结合小例子解释。

### 再想一步：如果恰好两边点数相同，就解决了吗？

也没有。比如 `x[:2]` 和 y 恰好都是 `(2, 3)`：

```python
# 只用于观察“直接相减”究竟会配哪些点，不是最终解决方案。
same_position_differences = x[:2] - y

print("\n===== 直接相减得到的是同位置行配对 =====")
print(same_position_differences)
```

```text
[[-0.11  1.27  3.45]
 [-4.6   1.5   3.34]]
```

这里第一行是 A−P，第二行是 B−Q。**没有 A−Q，也没有 B−P。**

所以，问题不只是本例“行数刚好对不上”：即使行数一样，直接相减也没有表达“每个 x 点都和每个 y 点比较”的需求。

但这里先别急着说“缺一条轴”。我们先重新看懂原数组保存什么，再看看比较结果比原数据多了哪一种需要区分的信息。

## 六、先设计需要保存什么，再决定需要几条轴

### 1. 原来的二维数组，指的是哪个数组？

指的就是课件一开始创建的 `x`。它并不是一个新对象，我们把原数据重新列出来：

```text
x = [
    [8.54, 1.54, 8.12],    第 0 行：点 A
    [3.13, 8.76, 5.29],    第 1 行：点 B
    [7.73, 6.71, 1.31]     第 2 行：点 C
]
```

NumPy 对这种二维数组的取值方式是 `x[行号, 列号]`。假如我们要取出其中的 5.29，先想一下：它在哪一行、哪一列？

它在第 1 行、第 2 列，编号从 0 开始，所以这样取：

```python
print("\n===== 原来的二维数组：先选行，再选列 =====")
print(x[1, 2])  # 得到 5.29
```

结合本案例的数据含义：

- 每行保存一个点，因此选行，就是选点。
- 每列保存一个坐标，因此选列，就是选这个点的一个坐标。

所以我们才把通用语法解释成：

```text
NumPy 的通用语法：x[行号, 列号]
                       ↓ 结合本案例的数据含义
本例中的含义：    x[点的编号, 坐标的编号]
```

**第二行只是解释性的写法，不是课件新增的一句代码，也不是要你把中文直接当下标写进程序。**

`x[1, 2]` 从表格位置来说是“第 1 行、第 2 列”，从案例含义来说就是“点 B 的第 2 个坐标”。数组只按位置取值；这些位置代表什么，是我们根据数据内容作出的解释。

因此，读取原 x 中一个具体的坐标，需要回答两个问题：选哪个 x 点？选这个点的哪个坐标？原来的 y 也是一样，只不过它保存的是 P、Q 两个点。

### 2. 开始比较以后，多了什么需要区分的信息？

先只拿 A 与 P 比较：

```text
A 的坐标：[8.54, 1.54, 8.12]
P 的坐标：[8.65, 0.27, 4.67]
对应相减：[-0.11, 1.27, 3.45]
```

这三个差值不再只是 A 的坐标，也不是 P 的坐标，而是属于 **“A 与 P 这一对点”**。

接着，A 还要和 Q 比较：

```text
A 的坐标：[8.54, 1.54, 8.12]
Q 的坐标：[7.73, 7.26, 1.95]
对应相减：[0.81, -5.72, 6.17]
```

先想一下：这两组差值能不加区分地混在一起吗？

不能。否则就不知道某个差值来自 A−P，还是 A−Q。所以保存比较结果时，除了知道“哪个 x 点”，还必须知道“它和哪个 y 点比较”。

**这不是原来的二维数组设计错了，而是“保存一组点”和“保存所有点对的比较结果”，需要记录的信息不同。**

### 3. 为什么说两个点编号需要独立选择？

固定 A，比较对象仍然可以改变：

```text
A 与 P 比较
A 与 Q 比较
```

固定 P，另一边的点也可以改变：

```text
A 与 P 比较
B 与 P 比较
C 与 P 比较
```

因此，“两个独立的点编号”只是说：**选择哪个 x 点，与选择哪个 y 点，是两个可以分别改变的选择。** 不是选了 A，就只能自动配 P；也不是在介绍一种新的索引语法。

### 4. 先把全部比较结果放进一张表

我们先回到最初的配对表，但暂时不把三个坐标差合成一个距离。每个格子先保存这一对点的三个坐标差：

| 起点 / 终点 | P | Q |
|---|---|---|
| A | A−P 的三个坐标差 | A−Q 的三个坐标差 |
| B | B−P 的三个坐标差 | B−Q 的三个坐标差 |
| C | C−P 的三个坐标差 | C−Q 的三个坐标差 |

### 5. 要取到某一个具体坐标差，需要回答几个问题？

假如要取出“A−Q 的第 2 个坐标差”，需要依次定位三次：

1. 选哪个 x 点？例如 A。
2. 选哪个 y 点？例如 Q。
3. 看哪一个坐标方向？例如第 2 个坐标。

我们把比较结果命名为 `diffs`，约定按这三个选择的顺序保存。三个选择分别对应三条轴，也可以分别用三个下标表示：

```text
i：x 点的编号，共 3 种选择
j：y 点的编号，共 2 种选择
k：坐标的编号，共 3 种选择
```

于是，中间结果需要的形状自然是：

```text
(3, 2, 3)
 │  │  └─ 同一对点的三个坐标差
 │  └──── 选择哪个 y 点
 └─────── 选择哪个 x 点
```

**这就是“三条轴”的来历。不是先规定一定要升成三维，而是我们确实有三个独立的问题需要分别定位。**

把具体下标代进去，更容易看清这套安排：

```text
diffs[0, 1, 2]
      │  │  └─ 取第 2 个坐标方向的差
      │  └──── 选 y 中的第 1 个点 Q
      └─────── 选 x 中的第 0 个点 A

这个位置应当保存：8.12 - 1.95 = 6.17
```

这里先是在设计结果应该怎样保存，`diffs` 还没有在代码里创建；后面才会用 NumPy 生成它。先明确每个位置应放什么，才能判断后续操作是否正确。

也可以把它想成一个文件柜：有 3 个抽屉，每个抽屉 2 个盒子，每个盒子放 3 个数。抽屉对应 x 点，盒子对应 y 点，盒子里的三个数对应坐标差。

这个中间数组有 3×2×3=18 个数，但它们只属于 6 对点。最终每个盒子的 3 个差值还要合成 1 个距离。

### 6. 再回头解释“给两个点编号各留一条轴”

更完整的说法是：原 x 只需要区分“哪个 x 点、哪个坐标”，原 y 只需要区分“哪个 y 点、哪个坐标”；但保存全部配对的坐标差时，需要同时区分“哪个 x 点、哪个 y 点、哪个坐标”，所以我们为中间结果设计了三条轴。

**原数组没有问题，改变的是我们要保存的信息。** 前面的双循环已经能正确计算全部距离，因此不是说计算两两距离必须建立三维数组。

我们接下来想尝试的是另一种表达方式：能不能先安排好数组的存放方式，再让 NumPy 通过一次数组相减，得到全部六对点的坐标差，而不由我们在 Python 中写两层循环逐对指定？

这里“配对”就是选一个 x 点和一个 y 点组成一次比较，例如 A 与 P、A 与 Q；“批量处理”是把这些比较交给数组运算表达，而不是省略其中任何一次计算。六对点仍然都要比较，不是写成一次运算就只计算了一对。

为了判断这种做法是否可行，我们先弄清楚 x、y 的轴应该怎样摆放，再解释 NumPy 怎样让它们配合运算。这个配合机制有专门的名字，但现在先不背术语，第九部分会从一个小例子介绍它。

接下来的问题才自然出现：x、y 原本都是二维数组，怎样调整它们的轴位置，为“选 x 点、选 y 点、选坐标”这三个选择做好准备？这就是后面引入 reshape 的原因。仅仅 reshape 还不会生成全部点对，它只负责调整形状；是否真的得到全部比较，要等实际相减后再验证。

## 七、从“三个下标各管什么”推导 x 应该怎样变形

现在约定三条轴依次是：

```text
(x 点编号, y 点编号, 坐标编号)
```

**这个顺序是我们为了组织比较结果而选择的，不是 NumPy 强制规定的。** 一旦选定，后续输入的轴位置、索引和求和方式，都要配合这套顺序。

### 先想一下：x 自己有哪些信息？又缺少哪一种信息？

x 自己知道：

- 自己有 3 个点，所以能回答第一个问题。
- 每个点有 3 个坐标，所以能回答第三个问题。

但是，x 自己并不按 y 点分组。对于同一个 x 点，不管接下来拿 P 还是 Q 来比较，**这个 x 点的坐标都是同一份**。

### 为什么新轴放在中间，而不是开头或末尾？

先不要猜位置。把 x 已有的两种信息，放到刚才约定的三个位置中：

| 约定的位置 | 第 0 轴：x 点 | 第 1 轴：y 点 | 第 2 轴：坐标 |
|---|---|---|---|
| x 已有的信息 | 3 个 x 点 | 没有按 y 点分组 | 每点 3 个坐标 |

空出来的恰好是中间的 y 点位置，所以才在中间插入一条长度为 1 的轴。

这里的 1 **不是说 y 只有一个点**。它表示 x 在这个位置先只有一份内容：后面不管拿 P 还是 Q 来比较，都使用同一个 x 点的坐标。实际怎样反复使用，等第九部分再验证。

```text
原来 x： (3,    3)
含义：   x 点   坐标

对齐后： (3, 1, 3)
含义：   x 点  │ 坐标
              └─ y 点这个位置暂时只有一份
```

这时才引入课件中的这一行：

```python
# 数组方法 reshape 的位置参数，在这里依次是新形状的三个长度。
# 3×1×3 仍然是 9 个元素，所以能重新安排形状，没有增加数值。
reshaped_x = x.reshape(3, 1, 3)

print("\n===== x 在中间增加长度为 1 的轴 =====")
print(reshaped_x)
```

```text
[[[8.54 1.54 8.12]]

 [[3.13 8.76 5.29]]

 [[7.73 6.71 1.31]]]
```

### 括号变多了，到底多出了什么？

我们别凭括号猜，直接取值：

```python
print("\n===== 取 x 的第 0 个点、唯一的第 0 份坐标 =====")
print(reshaped_x[0, 0])

print("\n===== 两种索引取到的是同一个原始数值 =====")
print(reshaped_x[0, 0, 1])
print(x[0, 1])
```

```text
[8.54 1.54 8.12]

1.54
1.54
```

所以 `reshaped_x[i, 0, k]` 对应的仍然是原来的 `x[i, k]`。

**增加轴不是添加一个坐标，也不是已经复制出了两份点。只是给索引增加了一个位置，这个位置当前只能填 0。**

### 如果在开头加轴，哪里和当前约定对不上？

在开头加轴会得到 `(1, 3, 3)`。原来表示“3 个 x 点”的那条轴，现在位于第 1 轴；但当前约定第 1 轴负责 y 点，这就对不上了：

```text
当前约定的位置： (x 点, y 点, 坐标)
开头增轴后的长度：(  1,    3,    3)
                          ↑
                  原来属于 x 点的轴跑到了这里
```

数值没有丢失，也不是 reshape 本身出错，而是这套排列没有配合我们选定的轴职责。

### 如果在末尾加轴呢？

得到 `(3, 3, 1)`。原来表示“三个坐标”的轴仍在第 1 轴，但我们约定坐标应该位于第 2 轴：

```text
当前约定的位置： (x 点, y 点, 坐标)
末尾增轴后的长度：(  3,    3,    1)
                          ↑
                  原来的坐标轴占到了 y 点的位置
```

所以，对于当前 `(x 点, y 点, 坐标)` 这个安排，x 才需要在中间增轴。

### 开头、末尾增轴，永远都不可以吗？

不是。**换一种轴顺序，并配套调整其他操作，也可以完成任务。**

例如，一开始如果约定顺序为 `(y 点, x 点, 坐标)`，那么 x 缺少的就是开头的 y 点位置：

| 换一种约定后的轴职责 | y 点 | x 点 | 坐标 |
|---|---:|---:|---:|
| x 调整后的形状 | 1 | 3 | 3 |
| y 配套调整后的形状 | 2 | 1 | 3 |

这时 x 在开头增轴就是合理的；相应的比较结果按 `(y 点, x 点, 坐标)` 存放，最终距离表也改成“行对应 y 点、列对应 x 点”的 2×3 排列。

同理，如果选择把坐标安排在中间、把 y 点安排在最后，x 就可以在末尾给 y 点留位置；但 y 的形状和后面合并坐标的轴也都要配套改变，不能只改 x 这一行。这里先理解选择位置的原因，后续继续沿用课件的安排，不另换一套写法。

因此，判断顺序应该是：

> **先选定各条轴的职责 → 看 x 已有的信息对应哪些位置 → 在缺少的位置插入轴。**

不是先认定“中间加轴才对”，再反过来找理由。数组能 reshape 成功，只说明元素数量兼容，不代表轴的含义已经符合当前任务。

## 八、用同样的理由推导 y 的形状

### 先想一下：同一个 y 点与 A、B、C 比较时，自己的坐标需要变吗？

不需要。P 不会因为比较对象换成 A、B、C，就改变自己的位置。

所以 y 不需要按不同 x 点各存一份数据。它在第一条轴上先放长度 1；第二条轴保存自己的 2 个点，第三条轴保存每点的 3 个坐标：

```text
原来 y： (   2, 3)
含义：       y 点 坐标

对齐后： (1, 2, 3)
含义：    │ y 点 坐标
          └─ x 点这个位置暂时只有一份
```

```python
reshaped_y = y.reshape(1, 2, 3)

print("\n===== y 在开头增加长度为 1 的轴 =====")
print(reshaped_y)
```

```text
[[[8.65 0.27 4.67]
  [7.73 7.26 1.95]]]
```

现在 `reshaped_y[0, j, k]` 对应原来的 `y[j, k]`。

把两边放在一起，才看得见这两次 reshape 配合的目的：

| 轴的职责 | 第 0 轴：x 点 | 第 1 轴：y 点 | 第 2 轴：坐标 |
|---|---:|---:|---:|
| reshaped_x | 3 | 1 | 3 |
| reshaped_y | 1 | 2 | 3 |

我们没有把两个数组变成相同形状，而是让它们在**自己没有变化需求的位置**保留长度 1。但形状不同，为什么还可能相减？接下来需要解释 NumPy 会怎样处理这些长度为 1 的位置。

## 九、先认识广播，再验证它怎样完成所有配对

### 先想一下：三个数为什么可以分别减去同一个数？

在看两个三维数组之前，先试一段更小的运算：

```python
broadcast_example = np.array([10, 20, 30])

print("\n===== 三个数分别减去同一个数 =====")
print(broadcast_example - 1)
```

```text
[ 9 19 29]
```

左边有三个数，右边只有一个数，为什么还能相减？因为 NumPy 可以让右边这个 1 分别用于三个位置：

```text
第 0 个位置：10 - 1 = 9
第 1 个位置：20 - 1 = 19
第 2 个位置：30 - 1 = 29
```

**这种让形状不完全相同的输入，按照规则配合运算的机制，叫作广播（broadcasting）。** 上面是数组与标量配合的简单例子；同样的机制也可以用于符合规则的两个数组。

但是，广播不等于“自动生成所有配对”。这个例子只是每项减同一个数，根本没有两组点。广播只遵守形状规则，不知道我们的业务目标；必须安排好输入的轴位置，才能让实际运算符合“所有点交叉比较”的需要。

### 先想一下：两个数组形状不同，怎样判断能不能逐项运算？

NumPy 广播从最右边开始，对齐各条轴。每一对长度满足下面任意一个条件，就能兼容：

- 两个长度相等；
- 其中一个长度是 1。

长度不同时，长度 1 的一侧会在运算中重复使用唯一位置的内容。

把刚才两组形状逐轴代入，而不是死记结果：

```text
                     x 点   y 点   坐标
reshaped_x.shape = (   3,     1,     3 )
reshaped_y.shape = (   1,     2,     3 )
------------------------------------------------
结果的 shape      = (   3,     2,     3 )
```

从右往左检查：

1. 坐标轴：3 和 3 相等，三个坐标逐项对应。
2. y 点轴：1 和 2 兼容，同一个 x 点可以分别和两个 y 点比较。
3. x 点轴：3 和 1 兼容，同一组 y 点可以分别给三个 x 点使用。

因此，才有：

```python
diffs = reshaped_x - reshaped_y

print("\n===== 所有配对的坐标差形状 =====")
print(diffs.shape)
```

```text
(3, 2, 3)
```

### 不要只看形状：真正发生的配对顺序是什么？

固定第 0 个 x 点，也就是 A：

```text
diffs[0, 0] = A - P
diffs[0, 1] = A - Q
```

固定第 1 个 x 点，也就是 B：

```text
diffs[1, 0] = B - P
diffs[1, 1] = B - Q
```

固定第 2 个 x 点，也就是 C：

```text
diffs[2, 0] = C - P
diffs[2, 1] = C - Q
```

前面的双循环在做这六件事；这里的广播也在做这六件事。变化的是配对工作的表达方式，不是距离的定义。

### 课件第 49 页那些“叠起来的表”，该怎样读？

先别把图中的前后叠放理解为“原来的点又增加了空间坐标”。图是在展示数组分组，不是在画仓库中的实际位置。

可以把三维数组暂时看成“一叠纸”：第 0 轴选第几张纸，第 1 轴选纸上第几行，第 2 轴选行里第几个数。

```text
x.reshape(3, 1, 3)：3 张纸，每张 1 行，每行 3 个数
    第 0 张：A 的坐标
    第 1 张：B 的坐标
    第 2 张：C 的坐标

y.reshape(1, 2, 3)：1 张纸，纸上 2 行，每行 3 个数
    第 0 张：第一行 P 的坐标，第二行 Q 的坐标
```

接下来两边要在 `(3, 2, 3)` 上做逐项相减，逻辑上对应：

```text
                    x 这一侧             y 这一侧
第 0 张的两行：     [A 的坐标]           [P 的坐标]
                   [A 的坐标]           [Q 的坐标]

第 1 张的两行：     [B 的坐标]           [P 的坐标]
                   [B 的坐标]           [Q 的坐标]

第 2 张的两行：     [C 的坐标]           [P 的坐标]
                   [C 的坐标]           [Q 的坐标]
```

为什么 x 在同一张纸上重复，而 y 在不同纸上重复？因为 x 的第 1 轴长度为 1，要配合 y 的两行；y 的第 0 轴长度为 1，要配合 x 的三张纸。长度为 1 的位置，恰好说明了哪一份内容可以被反复使用。

图中哪张纸画在前、哪张画在后只是透视排版；实际第几层由数组索引决定，不能仅凭视觉上最靠前的位置认定它是第 0 层。

> “重复使用”是理解广播的说法，不表示先实际复制出两份 x、三份 y。通常不必显式复制输入；但这里相减产生的 diffs 本身确实需要保存 18 个差值。

## 十、终于可以解释 diffs[i, j, k] = x[i, k] - y[j, k]

这句话应当读作：

> 在 diffs 中，取“第 i 个 x 点、第 j 个 y 点、第 k 个坐标”的差值，等于原 x 第 i 行第 k 列减去原 y 第 j 行第 k 列。

它是对结果每个元素的**对应关系说明**。如果没有先定义 i、j、k，它不是一行可以单独复制运行的完整程序。

### 先想一下：为什么 x 的下标里没有 j，y 的下标里没有 i？

因为选定一个 x 点后，它自己的坐标不取决于你拿哪个 y 点来比较；同理，选定一个 y 点后，它自己的坐标不取决于你拿哪个 x 点来比较。

把广播前的索引关系写完整，就能看出原因：

```text
diffs[i, j, k]
    = reshaped_x[i, 0, k] - reshaped_y[0, j, k]
    = x[i, k]             - y[j, k]
```

两个 `0` 来自哪里？

- reshaped_x 的 y 点轴长度只有 1，所以始终取该轴第 0 项。
- reshaped_y 的 x 点轴长度只有 1，所以始终取该轴第 0 项。

### 拿一个具体下标验证，而不是只相信字母

```python
print("\n===== diffs[0, 1, 2] 到底取了哪个差值 =====")
print(diffs[0, 1, 2])

print("\n===== 回到原始数组手工取相同的两个数 =====")
print(x[0, 2] - y[1, 2])
```

两次都约为 `6.17`：

```text
i=0：选 A
j=1：选 Q
k=2：看第 2 个坐标

x[0, 2] = 8.12
y[1, 2] = 1.95
8.12 - 1.95 = 6.17
```

再比较两种取法：

```python
print("\n===== 固定两个点：拿到三个坐标差 =====")
print(diffs[0, 1])

print("\n===== 再指定坐标：只拿到其中一个差值 =====")
print(diffs[0, 1, 2])
```

```text
[ 0.81 -5.72  6.17]

6.17
```

现在应该能区分：`diffs[i, j]` 是某一对点的完整差向量；`diffs[i, j, k]` 只是其中一个坐标差。

## 十一、把整个差值数组展开，看看每一层括号代表什么

```python
print("\n===== 所有配对的坐标差 =====")
print(diffs)
```

```text
[[[-0.11  1.27  3.45]
  [ 0.81 -5.72  6.17]]

 [[-5.52  8.49  0.62]
  [-4.60  1.50  3.34]]

 [[-0.92  6.44 -3.36]
  [ 0.00 -0.55 -0.64]]]
```

我们按刚才建立的索引含义读它：

```text
第 0 个大块：A 对所有 y 点
    第一小行：A - P 的三个坐标差
    第二小行：A - Q 的三个坐标差

第 1 个大块：B 对所有 y 点
    第一小行：B - P 的三个坐标差
    第二小行：B - Q 的三个坐标差

第 2 个大块：C 对所有 y 点
    第一小行：C - P 的三个坐标差
    第二小行：C - Q 的三个坐标差
```

这时，我们还没有得到距离表。原因是每一对点还保存着三个方向差异，而一个距离需要把这三项合并。

下一步就需要决定：**求和究竟应该合并哪条轴？**

## 十二、为什么是 axis=2：从“哪些信息该保留”推出来

先只做平方，不合并：

```python
# 每个坐标差分别平方，所以形状不变，仍是 (3, 2, 3)。
squared_diffs = diffs ** 2

print("\n===== 平方后的形状仍然包含三条轴 =====")
print(squared_diffs.shape)
```

### 先想一下：求和结束后，我们还需要知道“哪个 x 点”和“哪个 y 点”吗？

需要。否则就不知道一个距离属于哪一对点。

因此，第 0 轴的 x 点编号必须保留，第 1 轴的 y 点编号也必须保留。

我们不再需要把三个坐标方向分别保存，而是要把它们对同一段距离的贡献合起来。因此，应该沿第 2 轴求和：

```python
# axis=2 表示沿第三条轴归并，也就是同一对点的三个坐标方向。
# 默认 keepdims=False：这条轴在求和后的结果中不再保留。
squared_distances = np.sum(squared_diffs, axis=2)

print("\n===== 每对点的坐标差平方和 =====")
print(squared_distances)

print("\n===== 合并坐标方向后只剩两个点编号 =====")
print(squared_distances.shape)
```

```text
[[ 13.5275  71.4434]
 [102.9349  34.5656]
 [ 53.6096   0.7121]]

(3, 2)
```

这里第一个格子就是前面手算的：

```text
(-0.11)² + 1.27² + 3.45² = 13.5275
```

最后一个格子也可以核对：

```text
0² + (-0.55)² + (-0.64)²
= 0 + 0.3025 + 0.4096
= 0.7121
```

### 为什么不能用 axis=0、axis=1，或者干脆不写 axis？

| 写法 | 会合并什么 | 返回形状 | 为什么不符合当前任务 |
|---|---|---|---|
| `np.sum(squared_diffs, axis=0)` | 不同 x 点 | `(2, 3)` | 把不同起点的贡献混在一起 |
| `np.sum(squared_diffs, axis=1)` | 不同 y 点 | `(3, 3)` | 把到不同终点的贡献混在一起 |
| `np.sum(squared_diffs, axis=2)` | 同一对点的不同坐标 | `(3, 2)` | 正是我们要的每对点的距离平方 |
| `np.sum(squared_diffs)` | 所有轴上的全部值 | 标量 | 六对点都混在一起，丢掉配对信息 |

所以不要只记“第三维就用 axis=2”。你应该先问：**我要归并的是哪一种信息？这条信息此时在哪条轴上？**

本例坐标位于最后一条轴，也可以用 `axis=-1` 表示最后一条轴；结果相同。但轴的含义仍然要理解，不能只换成负数来躲开思考。

课件注释把这里的 axis=2 称为 column axis，可理解为每个点原本的坐标列。但到了三维数组，直接称“坐标轴 / 特征轴”更清楚，不要把它误认为最终距离表的列。

## 十三、为什么最后还要开平方，结果又该怎么读

我们当前算到的是距离的平方，不是距离本身。

```python
# 对六个平方和分别开平方，数组形状仍然为 (3, 2)。
dists = np.sqrt(squared_distances)

print("\n===== 最终的两两欧氏距离 =====")
print(dists)
```

```text
[[ 3.67797499  8.45241977]
 [10.14568381  5.87925165]
 [ 7.32185769  0.84386018]]
```

把数值放回最早设计的空表，才算真正回答了问题：

| 起点 / 终点 | P | Q |
|---|---:|---:|
| A | 3.67797499 | 8.45241977 |
| B | 10.14568381 | 5.87925165 |
| C | 7.32185769 | 0.84386018 |

### 先想一下：只看 0.84386018，你知道是哪一对点吗？

必须看它的位置：第 2 行、第 1 列，因此是 C 到 Q。

也可以直接从坐标验证为什么它很小：

```text
C = [7.73, 6.71, 1.31]
Q = [7.73, 7.26, 1.95]

三个方向的差是 [0, -0.55, -0.64]。
三个方向都很接近，所以距离约为 0.84386，与直觉一致。
```

这说明结果不只是“打印出一个矩阵”，而是每一行、每一列都有明确业务含义。

### 为什么还要和循环结果比较？

广播时轴放错，有时仍能得到某个看起来像表格的结果。代码不报错，并不能证明配对正确。

```python
# np.allclose(a, b) 检查两组数值是否在容许的浮点误差内接近。
# rtol 是相对容差，atol 是绝对容差；这里显式给出验证精度。
# 对每个位置的检查可理解为：|a-b| <= atol + rtol*|b|。
matches_loop = np.allclose(dists, loop_distances, rtol=1e-12, atol=1e-12)

print("\n===== 广播结果是否与双循环一致 =====")
print(matches_loop)

assert matches_loop
```

这里应为 True。我们同时检查了公式、配对含义和独立写法的结果，而不只是检查 shape。

## 十四、到这里，再回看课件的一行公式

课件第 50 页写的是：

```python
dists_from_slide = np.sqrt(np.sum(diffs ** 2, axis=2))
```

现在从里往外读，应该不再需要猜：

```text
diffs                      (3, 2, 3)：每一对点的三个坐标差
    ↓ 每个差分别平方
diffs ** 2                 (3, 2, 3)：每一对点的三个差平方
    ↓ 沿坐标轴求和，保留点对身份
np.sum(..., axis=2)         (3, 2)   ：每一对点的距离平方
    ↓ 每项开平方
np.sqrt(...)               (3, 2)   ：每一对点的欧氏距离
```

**为什么前面不直接从这一行开始讲？**

因为它压缩了三个不同的问题：哪些点配对、如何组织坐标差、怎样把坐标差变成距离。没有先解释这三件事，记住语法也不容易知道何时该换轴。

## 十五、课件第 51 页：不用 reshape，怎样自己推导另外两种写法

这页不是要你再背两套公式。距离公式不变，只换“怎样插入长度为 1 的轴”。

### 问题 A：如果保留原轴的位置，只想在中间插一条轴，索引怎么写？

先从 x 原本的两条轴出发：

```text
x[行选择, 坐标选择]
```

原有两条轴都要保留，所以各用一个 `:`；希望在它们中间插入新轴，就把 `np.newaxis` 放在两个冒号中间：

```python
# 第一个 : 保留全部 x 点，第二个 : 保留全部坐标。
# np.newaxis 在它出现的位置插入一条长度为 1 的轴。
x_with_axis = x[:, np.newaxis, :]

# y 缺的是开头的 x 点轴，因此把 np.newaxis 放在最前。
y_with_axis = y[np.newaxis, :, :]

print("\n===== newaxis 插入的轴是否在预期位置 =====")
print(x_with_axis.shape)
print(y_with_axis.shape)
```

```text
(3, 1, 3)
(1, 2, 3)
```

既然形状与每个数的对应关系都和前面一样，后续相减、平方、求和、开根号就没有理由改变：

```python
diffs_newaxis = x_with_axis - y_with_axis
dists_newaxis = np.sqrt(np.sum(diffs_newaxis ** 2, axis=2))

print("\n===== newaxis 方案是否得到相同距离 =====")
print(np.allclose(dists_newaxis, dists))
```

`np.newaxis` 本身就是 None 的别名，所以 `x[:, None, :]` 和 `x[:, np.newaxis, :]` 等价。它不是填入一个空数据，而是告诉索引操作增加一条轴。

### 问题 B：如果用函数指定插入位置，该传什么参数？

`np.expand_dims(a, axis)` 用于给数组增加长度为 1 的轴：

- `a` 是输入数组。
- `axis` 指定新轴在结果中的位置，不是要扩大的长度。

于是可以从前面的轴职责推出：

```python
# x：新轴位于结果的第 1 轴，夹在 x 点和坐标之间。
x_expanded = np.expand_dims(x, axis=1)

# y：新轴位于结果的第 0 轴，放在 y 点之前。
y_expanded = np.expand_dims(y, axis=0)

diffs_expanded = x_expanded - y_expanded
dists_expanded = np.sqrt(np.sum(diffs_expanded ** 2, axis=2))

print("\n===== expand_dims 方案是否得到相同距离 =====")
print(np.allclose(dists_expanded, dists))
```

这里的 `expand_dims(..., axis=1)` 是**插入轴**；上一节的 `sum(..., axis=2)` 是**归并轴**。虽然参数都叫 axis，但要结合函数用途理解，不能看到 axis 就认为总是在求和。

### 三种方法的共同点是什么？

| 目的 | reshape | newaxis | expand_dims |
|---|---|---|---|
| x 在中间增轴 | `x.reshape(3, 1, 3)` | `x[:, np.newaxis, :]` | `np.expand_dims(x, axis=1)` |
| y 在开头增轴 | `y.reshape(1, 2, 3)` | `y[np.newaxis, :, :]` | `np.expand_dims(y, axis=0)` |

共同点不是“都能让数组多一些括号”，而是都能把轴放成：

```text
x 的三个位置：(自己的 M 个点, y 点位置先只有 1 份, D 个坐标)
y 的三个位置：(x 点位置先只有 1 份, 自己的 N 个点, D 个坐标)

三个位置的职责始终统一为：(x 点, y 点, 坐标)
```

长度 1 的位置不增加任何坐标或特征，只让输入拥有兼容的轴位置；真正做相减时，同一份内容才按广播规则被反复使用。

## 十六、数据量改变以后，怎样让程序不依赖写死的 3、2、3

### 先想一下：如果 x 改成 100 行，`reshape(3, 1, 3)` 为什么会失败？

因为 reshape 要求新旧元素总数相同。原来写死的 3×1×3 只能容纳 9 个数，不能再代表 100 个三坐标点。

但任务的轴含义没变：

```text
x：M 个点，每点 D 个坐标          → (M, D)
y：N 个点，每点 D 个坐标          → (N, D)

差值：选 x 点、选 y 点、选坐标     → (M, N, D)
距离：保留 x 点和 y 点，合并坐标   → (M, N)
```

newaxis 不需要手动填写 M、N、D，所以更容易直接复用：

```python
# 前提：x、y 均为二维数值数组，且每点的坐标数量相同。
general_diffs = x[:, np.newaxis, :] - y[np.newaxis, :, :]
general_distances = np.sqrt(np.sum(general_diffs ** 2, axis=-1))

print("\n===== 不写死行数后的距离表 =====")
print(general_distances)
```

同样也可写通用 reshape：`x.reshape(x.shape[0], 1, x.shape[1])`，以及 `y.reshape(1, y.shape[0], y.shape[1])`。它们并不比 newaxis 更神奇，只是显式填写了新形状。

### 为什么必须强调“每点坐标数量相同”，不能只检查能不能广播？

因为我们要比较同一个方向的坐标。第 k 项必须在两组点里表达同一种含义。

如果 x 是三个坐标、y 只有一个坐标，某些形状仍可能发生广播，让一个数被重复用于三个方向；语法上可能能运行，业务上却不是我们定义的三坐标距离。

同理，若一组列顺序为“长、宽、高”，另一组为“高、长、宽”，形状虽然一致，直接相减仍会比较错字段。

所以形状兼容只是计算条件，不等于数据含义已经正确。

## 十七、把已经推导出的过程整理成一段可运行代码

这一节是回顾与验证，不是新的推导。建议看懂前面各步后，再整段运行。

```python
import numpy as np

x = np.array([
    [8.54, 1.54, 8.12],
    [3.13, 8.76, 5.29],
    [7.73, 6.71, 1.31],
], dtype=float)

y = np.array([
    [8.65, 0.27, 4.67],
    [7.73, 7.26, 1.95],
], dtype=float)

# .ndim 是数组的轴数；本案例要求行表示点、列表示坐标。
assert x.ndim == 2 and y.ndim == 2

# 同一个坐标位置必须在两组点中都有对应项。
assert x.shape[1] == y.shape[1]

# 先用双循环作为容易理解的参照。
loop_distances = np.zeros((x.shape[0], y.shape[0]), dtype=float)
for i in range(x.shape[0]):
    for j in range(y.shape[0]):
        difference = x[i] - y[j]
        loop_distances[i, j] = np.sqrt(np.sum(difference ** 2))

# 把“选 x 点”和“选 y 点”放在两条独立的轴上。
reshaped_x = x.reshape(x.shape[0], 1, x.shape[1])
reshaped_y = y.reshape(1, y.shape[0], y.shape[1])

print("\n===== 两个输入怎样对齐到三条轴 =====")
print(reshaped_x.shape)
print(reshaped_y.shape)

# 得到 (x 点, y 点, 坐标) 三条轴上的全部差值。
diffs = reshaped_x - reshaped_y

print("\n===== 每一对点的坐标差 =====")
print(diffs)

# 先分别平方，再只合并同一对点的坐标方向。
squared_diffs = diffs ** 2
squared_distances = np.sum(squared_diffs, axis=2)

print("\n===== 每对点的距离平方 =====")
print(squared_distances)

# 从平方距离还原为欧氏距离。
dists = np.sqrt(squared_distances)

print("\n===== 最终距离表：行对应 x 点，列对应 y 点 =====")
print(dists)

# 验证替代的两种增轴写法。
diffs_newaxis = x[:, np.newaxis, :] - y[np.newaxis, :, :]
diffs_expanded = np.expand_dims(x, axis=1) - np.expand_dims(y, axis=0)

assert np.allclose(diffs_newaxis, diffs)
assert np.allclose(diffs_expanded, diffs)
assert np.allclose(dists, loop_distances, rtol=1e-12, atol=1e-12)

print("\n===== 与双循环核对是否通过 =====")
print(np.allclose(dists, loop_distances, rtol=1e-12, atol=1e-12))
```

课件里的 `x: np.ndarray = ...` 比本篇的 `x = ...` 多了类型注解。它用来提示 x 预期是 NumPy 数组，不改变这里的距离算法，也不会自动验证数组形状。

## 十八、扩展：这套写法有什么代价，什么时候要小心

本节是课件案例之外的补充，先理解前面的配对与轴，再看这里。

### 问题：输入不用显式复制，是不是完全不占额外内存？

不是。`diffs` 要存 M×N×D 个差值；平方数组也可能再占用同量级内存，最后距离表还需要 M×N 个数。

例如 M=N=10000、D=3，差值数组含：

```text
10000 × 10000 × 3 = 300000000 个数
```

若每个 float64 占 8 字节，仅这个差值数组约为 24 亿字节，即 2.4 GB（十进制口径），还不包含平方数组和结果。

所以“小案例里一行就算完”不能推出“大数据里这样写总是最合适”。大数据可考虑分块计算，或使用专门的距离计算工具；本篇先不展开这些实现。

### 问题：数据本来就是整数，需不需要考虑类型？

需要。小整数类型做减法或平方时可能溢出，得到错误结果却不一定报错。真实输入可先使用 `np.asarray(data, dtype=float)` 转成浮点数组，再计算；仍要确保输入是有限数值，并留意非常大数值的溢出风险。

### 问题：不同列是年龄、收入、身高，也能直接这样比较吗？

能执行这套算式，不代表距离有合理含义。收入的数值尺度可能远大于年龄，结果容易被它主导；应先根据任务判断是否需要统一尺度、设置权重或改用其他度量。

本案例把三列视为相同长度单位下的空间坐标，所以可以直接应用普通欧氏距离。

## 十九、最后先自己回答，再核对原因

### 1. 为什么不是直接 x - y？

先自己说出它会怎样配对。

**参考推导：**直接相减按现有轴对齐；本例行数 3 与 2 不兼容。即使点数相等，也通常只比较同位置行，不能得到所有交叉组合。因此需要让两个点编号独立变化。

### 2. 为什么 x 要变成 (3, 1, 3)，而不是因为“课件就这么写”？

先为三个位置分别说出含义。

**参考推导：**中间结果需要 `(x 点, y 点, 坐标)`。x 有三个点、每点三个坐标，但同一个 x 点不因比较的 y 点变化而改变，因此在 y 点的位置先放唯一的一份，即长度 1。

### 3. y 为什么是 (1, 2, 3)？

试着用上一题相同的理由说明。

**参考推导：**y 有两个点、每点三个坐标，同一组 y 点给每个 x 点使用，所以在 x 点位置放长度 1，后面保留两个 y 点和三个坐标。

### 4. diffs[1, 0, 2] 表示什么？

先说业务含义，再取原始数值。

**参考推导：**x 第 1 个点 B，与 y 第 0 个点 P，比较第 2 个坐标；也就是 `x[1, 2] - y[0, 2] = 5.29 - 4.67 = 0.62`。它只是一个坐标差，不是 B 到 P 的距离。

### 5. 为什么沿 axis=2 求和？

先回答“哪些编号应该保留”。

**参考推导：**x 点编号、y 点编号必须保留，才能辨认距离属于谁；只有同一对点的坐标方向要合并，因此沿负责坐标的第 2 轴求和。它使 `(3, 2, 3)` 变为 `(3, 2)`。

### 6. 如果 x 有 4 个点、y 有 5 个点，每点 2 个坐标，形状会怎样变化？

不要照抄 3、2、3，先写每条轴的职责。

**参考推导：**输入是 `(4, 2)` 与 `(5, 2)`；增轴后是 `(4, 1, 2)` 与 `(1, 5, 2)`；差值是 `(4, 5, 2)`；沿坐标轴合并再开平方，得到 `(4, 5)`，共 20 个距离。

### 7. 这项知识解决什么类型的问题？当前案例为什么需要它？

**参考推导：**它解决“两组对象之间所有组合的比较”，这里具体算欧氏距离。因为一行表示一个点，且要求每个 x 点到每个 y 点都比较，所以需要两个独立的点编号，而不是同位置配对。

### 8. 每一步为什么出现在这个时刻？换一种做法有什么代价？

**参考推导：**先明确配对表，才知道最终保留哪些轴；先理解单对距离，才知道如何处理坐标差；先增轴，才能广播得到所有点对；先平方，再沿坐标轴求和，最后开根号。双循环直观、便于核对，且可少用巨大的差值中间数组，但 Python 层循环开销较大；广播把配对表达得紧凑，却要留意 M×N×D 的内存成本，不能只以代码长短判断好坏。
